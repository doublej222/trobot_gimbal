# Pitch 目标限位钳位分析与修正

> 结论：`gimbal.cc` 里「防止目标超过电机限位」的钳位少了一项 `ins->roll`，在底盘倾斜 / 云台不在某个特定角度时会把行程压成一半并产生正反馈。本文说明推导、数据对照与最终改法。

---

## 一、符号与物理关系

| 记号 | 含义 | 代码 |
| --- | --- | --- |
| `r` | 云台**对地**俯仰角（陀螺在云台上），`+` 为抬起 | `ins->roll`（rad） |
| `f` | 电机编码器角度 | `pitch_motor.feedback.pos`（rad） |
| `p` | 摇杆给出的**绝对目标** roll（rad） | `0 + rc_r[1]/660*0.5` |
| `c` | 底盘相对地面的俯仰角（轮腿不稳时会变） | 不可直接测，需估计 |
| `m` | 电机角 | 同上 `f` |

### 实测标定数据

| 状态 | `ins->roll` r (rad) | 电机角 m (rad) |
| --- | --- | --- |
| 抬起最大 | +0.347 | 0.74（最小） |
| 水平 | 0 | 1.12 |
| 下压最大 | −0.4 | 1.48（最大） |

由表可见：**抬起 → `r` 增大 → 电机角减小**，即 `r` 与电机角 **1:1 反相关**。一般化为（`r − c` 是云台相对底盘的角度）：

```
m = 1.12 − (r − c)
```

由此得到一个关键恒等式（底盘倾角只由它体现）：

```
f + r = 1.12 + c
```

> 注意：`1.12` 是**水平标定**时的电机角，底盘一歪，`r = 0` 就不再对应 `m = 1.12`。所以不能用固定的 `PITCH_ZERO_POINT` 去限位，必须用 `f + r` 实时估计底盘倾角。

---

## 二、正确的限位推导

目标是绝对角 `p`，云台到位后 `r = p`，那时电机角：

```
m_target = 1.12 − (p − c)
         = 1.12 − p + (f + r − 1.12)     // 代入 c = f + r − 1.12
         = f + r − p
```

要求机械不越界 `MIN ≤ m_target ≤ MAX`：

```
MIN ≤ f + r − p ≤ MAX

  ⟹   f + r − MAX  ≤  p  ≤  f + r − MIN
```

**即钳位上下界为：**

```
下界 lo = feedback.pos + ins->roll − PITCH_LIMIT_MAX
上界 hi = feedback.pos + ins->roll − PITCH_LIMIT_MIN
```

注意 `p` 与 `f + r` 单位都是 rad，全程一致。

---

## 三、原代码错在哪

原代码等效于：

```
p = clamp(p, f − MAX, f − MIN)
```

比正确式**少了 `+ ins->roll`**。`f` 单独不能代表底盘倾角，`f + r` 才能。因为少这一项，钳位界会随当前云台角度 `r` 漂移，形成**正反馈**。

### 3.1 水平底盘下的数值对照

底盘水平（`c = 0`），当前 roll 为 `r`，则 `f = 1.12 − r`。
摇杆推满 `p = 0.5` 时：

| 当前 r (rad) | f = 1.12−r | 旧上界 f−MIN | 旧目标 min(0.5, ·) | 新上界 f+r−MIN | 新目标 |
| --- | --- | --- | --- | --- | --- |
| 0 | 1.12 | 0.35 | 0.35 | 0.35 | 0.35 |
| 0.10 | 1.02 | 0.25 | 0.25 | 0.35 | 0.35 |
| 0.175 | 0.945 | 0.175 | 0.175（=当前，卡住） | 0.35 | 0.35 |
| 0.25 | 0.87 | 0.10 | 0.10（<当前，反向下拉） | 0.35 | 0.35 |

旧逻辑稳态满足 `r = 0.35 − r`：

| 方向 | 旧稳态 | 新稳态 |
| --- | --- | --- |
| 抬起 | `r = 0.175 rad ≈ 10.0°` | `r = 0.35 rad ≈ 20.1°` |
| 下压 | `r = −0.185 rad ≈ −10.6°` | `r = −0.37 rad ≈ −21.2°` |

症状：**推到一定程度就不动了，实际行程只有一半；越推越往下**。

### 3.2 底盘倾斜时的对照

底盘抬头 `c = +0.2`（`f + r = 1.32`）：

| 当前 r | f | 旧界 [f−1.49, f−0.77] | 新界 [f+r−1.49, f+r−0.77] |
| --- | --- | --- | --- |
| 0 | 1.32 | [−0.17, 0.55] | [−0.17, 0.55] |
| 0.2 | 1.12 | [−0.37, 0.35] | [−0.17, 0.55] |
| 0.4 | 0.92 | [−0.57, 0.15] | [−0.17, 0.55] |

旧界随当前 `r` 乱漂，新界只随底盘倾角 `c` 平移（正确）。

### 3.3 不同底盘倾角下的正确限位

| 底盘倾角 c (rad) | f + r | 新界 [lo, hi] (rad) | 物理含义 |
| --- | --- | --- | --- |
| −0.2 | 0.92 | [−0.57, +0.15] | 底盘低头，云台可下压更多 |
| 0 | 1.12 | [−0.37, +0.35] | 水平 |
| +0.2 | 1.32 | [−0.17, +0.55] | 底盘抬头，云台可上抬更多 |

由于界只依赖 `f + r`，而云台运动时 `f` 与 `r` 反向变化、其和保持不变，所以修正后是**负反馈、稳定**。

---

## 四、代码修改

保留三目写法，判断式与输出两端都补上 `+ ins->roll`：

```cpp
pitch_target = 0.f + static_cast<float>(rc->rc_r[1]) / 660.f * 0.5f;

pitch_target = (pitch_motor.feedback.pos + ins->roll - pitch_target) > PITCH_LIMIT_MAX ? pitch_motor.feedback.pos + ins->roll - PITCH_LIMIT_MAX :
(pitch_motor.feedback.pos + ins->roll - pitch_target) < PITCH_LIMIT_MIN ? pitch_motor.feedback.pos + ins->roll - PITCH_LIMIT_MIN : pitch_target ;

pitch_target = pitch_target * 180.f / fpi;
```

对应关系：

| 项 | 旧 | 新 |
| --- | --- | --- |
| 判断量 | `feedback.pos − p` | `feedback.pos + ins->roll − p` |
| 上钳输出 | `feedback.pos − MAX` | `feedback.pos + ins->roll − MAX` |
| 下钳输出 | `feedback.pos − MIN` | `feedback.pos + ins->roll − MIN` |

---

## 五、假设与注意事项

1. **1:1 反相关假设**：推导依赖 `m = 1.12 − (r − c)` 斜率为 `−1`。实测斜率 `(1.48−0.74)/(−0.4−0.347) ≈ 0.99`、端点反推零点 `≈1.084` 与水平读数 `1.12` 差约 `0.036 rad (~2°)`。存在约 1% 标度差 + 2° 零偏，`f + r` 会缓慢漂移，建议把这条映射标定准。
2. **零点自动消去**：修正式中不含 `PITCH_ZERO_POINT`，所以对你也担心的「1.12 不对应水平」天然免疫；但仍受第 1 点的标度/非线性影响。
3. **采样噪声**：`ins->roll` 与 `feedback.pos` 采样时刻不同，相加有噪声，必要时对 `f + r` 低通。
4. **符号极性**：确认摇杆上推使 `rc_r[1]` 为正（当前 `+` 被当作抬起）。
5. **`PITCH_LIMIT_MAX = 1.49`** 略大于实测机械上限 `1.48`，建议改为 `1.48` 留出余量。
